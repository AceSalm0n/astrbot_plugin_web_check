# WebCheck

![WebCheck 网站连通性检查](readme-banner.png)

[![License: AGPL v3](https://img.shields.io/badge/License-AGPL%20v3-blue.svg)](LICENSE)

WebCheck 是 AstrBot 网站连通性检查插件，支持单站点、多站点和配置列表检查。检查结果反映 AstrBot 所在服务器的网络状况。

## 安装

在 AstrBot 插件市场安装，或将仓库克隆到 AstrBot 的 `data/plugins/astrbot_plugin_web_check/` 目录。在 AstrBot 使用的 Python 环境中安装依赖，再重载插件：

```bash
python -m pip install -r requirements.txt
```

## 指令

| 指令 | 说明 |
| --- | --- |
| `/check <url> [url2 ...]` | 单站点返回详情；多个目标返回汇总，空白分隔 |
| `/批量检查` | 检查配置的 watchlist，默认仅 AstrBot 管理员可用 |
| `/check列表` | 展示列表及逐项输入错误，默认仅 AstrBot 管理员可用，不发起 DNS 或 HTTP 请求 |
| `/check状态` | 查看配置和 HTTP 会话状态 |
| `/check帮助` | 查看帮助 |

以上示例使用 `/` 唤醒前缀，实际使用应以 AstrBot 后台配置为准。例如后台前缀为 `#` 时，使用 `#check www.baidu.com`、`#批量检查`。

网址省略协议时补 HTTPS，只接受 HTTP/HTTPS，检查主机与端口，拒绝含用户名或密码的地址。回复中的 URL 只显示协议、主机与端口，路径、全部查询参数及片段均隐藏；实际请求仍使用完整 URL。watchlist 中的无效目标逐项反馈，不影响其他目标。

## 检查行为

- 默认优先 HEAD，遇到 405 释放响应后回退 GET。GET 最多读取 64 KiB，达到预算即停止；区分服务器声明长度与实际读取长度，注明截断。关闭自动解压，读取预算按传输正文计算。
- 默认验证 HTTPS 证书；关闭 `verify_ssl` 后，结果明确提示未验证。默认不跟随重定向；开启后手动跟随，最多 5 跳，每跳重新校验 URL 和实际连接地址。
- 实际连接器校验 DNS、缓存结果及 IP 字面量。非公网、多播、保留地址及映射到受限 IPv4 的 IPv6 地址均被拦截；混合公网与受限地址的解析也会被拒绝。保留域名用于 Host/SNI。
- 单站点总期限从取得共享并发名额后开始，覆盖 DNS、请求、HEAD 回退、跳转、正文和重试等待，不包含并发排队。仅暂时性连接错误重试，等待依次为 0.5、1、2 秒；输入错误、安全拦截、证书错误、永久解析错误及 HTTP 错误不重试。
- 会话不保存 Cookie。卸载时阻止新检查，取消并等待在途任务后关闭会话，重复卸载安全。

## 配置

在 AstrBot 管理后台的插件配置中修改。默认值统一读取 [_conf_schema.json](_conf_schema.json)，缺失配置使用默认值，错误类型或越界值明确报错。

| 配置项 | 类型 | 默认值 | 范围或行为 |
| --- | --- | --- | --- |
| `check_timeout` | int | 10 | 1–120 秒，单站点总期限 |
| `max_concurrent` | int | 5 | 1–20，跨命令共享 |
| `max_dns_tasks` | int | 5 | 1–20，未完成的底层 DNS 解析上限；HTTP 会话创建时固定，修改后重载生效 |
| `max_pending_targets` | int | 200 | 1–1000，所有在途批次的目标预留总量，含执行和排队；容量不足整批拒绝 |
| `queue_timeout` | int | 30 | 1–120 秒，取得并发名额前的等待上限 |
| `retry_count` | int | 1 | 0–3，暂时性连接错误的重试次数 |
| `max_sites` | int | 50 | 1–100，命令输入或 watchlist 超限均拒绝整次检查 |
| `use_head` | bool | true | HEAD 优先，405 回退 GET |
| `follow_redirects` | bool | false | 手动跟随，最多 5 跳 |
| `verify_ssl` | bool | true | HTTPS 证书验证 |
| `user_agent` | string | `Mozilla/5.0 (compatible; AstrBot-WebCheck/2.0)` | 1–256 字符，无控制字符 |
| `watchlist` | list | 下列四个 HTTPS 地址 | 保留已有列表；显式空列表保持为空；无效条目逐项反馈 |
| `watchlist_admin_only` | bool | true | 列表查看和批量检查仅 AstrBot 管理员可用；设为 false 恢复可信会话中的公开使用 |

默认列表为 `https://www.baidu.com`、`https://www.google.com`、`https://www.github.com`、`https://www.bing.com`。

从 2.0.3 起，`/check列表` 和 `/批量检查` 默认需要 AstrBot 管理员身份；QQ群管理员身份本身不授予此权限。已有配置缺少 `watchlist_admin_only` 时同样按 true 处理。需要保留公开使用方式的部署可显式设为 false，并配置 AstrBot 白名单和限流；普通 `/check <url>` 仍可使用。所有用户的 URL 展示均执行脱敏。

每批开始时固定已验证的配置和目标列表；批次进行中修改超时、重试、TLS 等设置不会改变该批次策略，新设置用于下一批。User-Agent 按请求发送，后续批次无需重建会话即可使用新值。检查进行中变更 `max_concurrent` 后，新检查会提示等待在途检查结束再重试，避免多个并发限制同时生效。

## 结果说明

网络失败提示区分 DNS 解析、连接被拒绝、服务器断连、TLS 验证、连接/响应超时和正文中断；只使用预设说明，不回显原始异常。解析到 IPv4/IPv6 基准测试保留地址时，提示“可能是代理 Fake-IP”并继续拦截；这是地址特征提示，不代表已经确认代理故障。

每批接纳时预留全部目标容量，直到该批结束、取消或卸载才统一归还，避免连续命令无限堆积。排队超时逐项返回结果，不取消其他正在执行的检查；`queue_timeout` 与取得名额后的 `check_timeout` 分别计时。

DNS 解析另有容量限制：检查超时或取消后，尚未完成的底层解析继续占用 DNS 名额，实际结束后才释放；同一 AstrBot 上下文中的插件重载会继承旧解析的占用量。容量用尽时返回“DNS 解析繁忙，请稍后重试”，不会自动重试或继续堆积解析工作；IP 字面量和有效 DNS 缓存仍按原安全规则检查。`/check状态` 可查看 DNS 占用量及当前生效上限。

结果分别统计 2xx 正常响应、3xx 重定向、4xx/5xx HTTP 错误、网络失败、安全拦截和输入错误。204 属于正常响应，404/500 计入 HTTP 错误。另行统计“HTTP 有响应”，包括错误状态码以及收到响应头后正文超时的目标。

汇总包含全部条目，异常目标排列在前，消息自动分段，每条不超过 1800 字符。响应耗时记录从检查开始到收到当前响应头的时间，包括此前跳转与重试等待；不包含后续正文读取时间。

## 使用注意事项

### TUN、代理与 Fake-IP DNS

开启 TUN 并配合 Fake-IP DNS 时，域名可能解析到 `198.18.0.0/15`、`2001:2::/48` 等保留地址。插件会在建立连接前将这些地址安全拦截，因此可能出现“浏览器能访问，插件却提示安全拦截”的情况；单站点和批量检查都会受到影响。

TUN 与 Fake-IP 是不同设置：TUN 负责接管网络，DNS 模式决定是否返回虚拟地址。出现相关提示时，请检查 AstrBot 所在环境的 DNS 结果，让需要检查的域名返回真实公网 IP；可根据代理客户端的配置，为这些域名设置 Fake-IP 过滤。更改后应重新确认解析结果并重试，旧 DNS 缓存可能仍有影响。

“安全拦截”表示插件未向该目标发起实际连接，不能据此判断网站宕机。插件仍会拒绝私有、环回、链路本地、多播等受限地址；Fake-IP 提示仅说明地址特征，不能单凭该提示确定代理故障。

### HTTPS 证书与检查结果

默认验证 HTTPS 证书。证书过期、证书与域名不匹配或证书链不受信任时，检查会显示 HTTPS/TLS 验证失败；这表示安全校验生效。域名被 Fake-IP 拦截时，检查尚未进入 TLS 握手，调整 `verify_ssl` 无法解决该阶段的问题。

`verify_ssl=false` 会降低 HTTPS 检查的安全性，结果将明确标注未验证。HTTP 4xx/5xx 表示服务器已有响应，但请求返回错误；重定向是否继续访问由 `follow_redirects` 决定。

### 网络环境与使用范围

检查反映 AstrBot 服务器当时的 DNS、路由、防火墙和代理环境，不代表你手机或电脑浏览器的访问结果。超时也可能与服务器网络有关，不能仅凭一次失败判定网站故障。

每次目标数、共享并发、待处理容量和排队时间均有上限。遇到“检查繁忙”“排队超时”或“超过上限”时，可稍后重试或拆分目标；调整并发配置后，应等待在途批次结束再发起新检查。

## 风险提示与免责声明

本插件按“现状”提供，用于辅助判断 AstrBot 服务器的网络连通性，不保证检查结果始终准确、目标服务持续可用或运行环境不存在安全风险。请结合实际部署环境评估以下风险：

- **指令开放与资源占用**：能够调用检查指令的用户可以让服务器向公网目标发送请求。插件的共享并发和容量限制不等于按用户或群分配的公平限额，持续调用可能挤占其他检查资源，或触发目标站点的限流、封禁。公开使用前应核实 AstrBot 的白名单和限流配置，仅检查有权访问的目标。
- **慢 DNS 任务残留**：底层解析可能在检查超时后继续运行，但仍占用独立的 DNS 容量，不会因检查结束而提前释放名额。Python 无法安全强制终止已经执行的系统 DNS 调用；遇到持续超时或 DNS 繁忙时应降低调用频率并排查 DNS，不应反复重载或持续调高容量来规避限制。
- **敏感地址泄露**：回复隐藏路径、查询参数和片段，但主机名与端口仍可见；目标服务器仍会收到完整请求 URL。不要在 watchlist 中存放含令牌、密码、私有下载凭据或一次性访问链接的地址，并保护 AstrBot 配置和聊天记录。将 `watchlist_admin_only` 设为 false 会向能调用列表指令的用户公开目标主机信息。
- **TLS 与网络边界**：关闭 `verify_ssl` 会失去 HTTPS 证书身份校验，存在中间人攻击风险。TUN、透明代理、特殊路由及 IPv6 转换等环境会影响实际访问路径；地址校验不能替代宿主的网络隔离和出站防火墙策略，Fake-IP 拦截也不能用于判断网站是否故障。
- **读取预算与依赖变化**：64 KiB 是 GET 正文的应用层读取预算，不是总网络流量或峰值内存的严格上限。插件依赖 aiohttp 的连接器内部接口，更新 Python、AstrBot 或 aiohttp 后，应重新确认地址拦截、超时及卸载行为。

部署者应妥善设置访问权限、保护配置与凭据，并遵守目标站点的使用规则及适用法律。检查结果不应作为服务可用性或安全性的唯一判断依据；具体许可、担保排除及责任限制以 [LICENSE](LICENSE) 为准。
